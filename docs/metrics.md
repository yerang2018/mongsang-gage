# 몽상가게 행동 지표·AI 원가 측정

"처음 온 사람이 구매 이유를 이해하고, 친구에게 공유하고, 다시 오는지"를 확인하려고 기록하는 숫자들을 정리했어요.
관리자 대시보드는 없어요. 운영자가 아래 방법으로만 볼 수 있어요.

## 1. 적용하는 법 (한 번만)

1. Supabase 대시보드 → SQL Editor에 `supabase/migrations/0011_metrics.sql` 전체를 붙여 넣고 Run 하세요.
   - 기존 데이터는 바꾸지 않아요. `events` 표에 칸 3개를 더하고, `ai_calls`·`metrics_excluded_users` 표와 `metrics_report` 함수를 만들어요.
   - 미리 내 컴퓨터에서 검사할 수 있어요: `npx tsx scripts/check-sql.ts`
2. 그다음 앱을 배포하세요: `npx --yes vercel@latest deploy --prod --yes`
   - 순서가 바뀌어도 화면은 정상으로 떠요. 다만 0011을 적용하기 전에 생긴 방문·공유·AI 호출은 기록되지 않아요.
3. 운영자·시험 계정을 지표에서 빼 주세요. SQL Editor에서 실행해요. 닉네임은 실제 내 시험 계정 이름으로 바꿔 넣으세요.

```sql
insert into public.metrics_excluded_users (user_id, note)
select id, '운영자 시험 계정' from public.profiles where nickname in ('무니')
on conflict do nothing;
```

   - 넣은 계정이 판 거래나 산 거래, 그 계정으로 로그인했던 기기(방문자 번호)의 기록은 모두 빠져요.
   - 예전 거래를 "시험 거래"로 따로 표시하지는 않아요. 어떤 계정을 뺄지는 운영자가 정해요.

## 2. 보는 법

- 터미널(샌드박스 밖)에서 실행해요:
  `npx tsx --env-file=.env.local scripts/metrics.ts 2026-11-01 2026-11-14`
  날짜는 한국 날짜이고, 처음과 끝 날을 모두 포함해요. 날짜를 생략하면 최근 7일을 보여 줘요.
- 또는 SQL Editor에서 실행해요: `select * from public.metrics_report('2026-11-01', '2026-11-14');`
- `metrics_report`는 서버 비밀 키(service_role)로만 실행돼요. 앱의 공개 키나 로그인한 사용자로는 실행할 수 없어요.
  `ai_calls`·`metrics_excluded_users` 표도 보안 규칙(RLS) 때문에 앱에서는 읽을 수 없어요.

## 3. 지표 정의

이 문서에서 쓰는 말:
- **기간**: 위에서 넣은 시작일~종료일 (한국 시간, 양 끝 포함)
- **방문자**: 기기 하나. 쿠키 `kk_vid`에 저장한 무작위 번호로 구분해요.
- **핵심 행동**: 꿈 기록, 판매 등록, 꿈 구매, 꿈 구해요 등록, 꿈 구해요에 꿈 내밀기

| # | 지표 | 분자 | 분모 | 출처 |
|---|---|---|---|---|
| 1 | 첫 방문 | 기간 안에 처음 온 방문자 수 | 없음 | `events.first_visit` (방문자마다 1번) |
| 2 | 닉네임 설정 완료 | 기간 안에 생긴 계정 중 닉네임을 정한 계정 | 기간 안에 생긴 계정 (익명 시작 포함) | `profiles` |
| 2b | 첫 방문 → 닉네임 | 1의 방문자 중 닉네임을 정한 계정과 연결된 방문자 | 1 | `events.session_link` + `profiles` |
| 3 | 첫 꿈 저장 | 2의 분자 중 꿈을 1개 이상 저장한 사람 | 2의 분자 | `dreams` |
| 3b | 저장된 꿈 수 | 기간 안에 저장된 꿈 | 없음 | `dreams.created_at` (해몽에 성공해 저장된 것만) |
| 4 | 판매 등록 | 기간 안에 판매 등록된 꿈 | 없음 | `dreams.listed_at` |
| 4b | 판매 등록한 사람 | 기간 안에 판매 등록한 사람 | 기간 안에 꿈을 저장한 사람 | `dreams` |
| 5 | 공유 시도 | 공유 창 열기 + 링크 복사 누름 | 없음 | `events.share_attempt` |
| 5b | 공유 창 완료 | 공유 창에서 앱을 고름 | 공유 창 열기 | `events.share_complete` |
| 5c | 링크 복사 완료 | 클립보드 복사 성공 | 없음 | `events.link_copied` |
| 5d | 공유 창 취소 | 공유 창을 그냥 닫음 (성공으로 세지 않음) | 없음 | `events.share_cancel` |
| 6 | 공유 링크 방문 | `?via=share/copy` 링크로 들어온 방문자 (판 사람·요청한 사람 본인 제외, 같은 링크는 1번) | 없음 | `events.share_visit` |
| 6b | 공유 링크 방문 → 닉네임 | 6 중 닉네임을 정한 계정과 연결된 방문자 | 6 | |
| 7 | 꿈 구매 성공 | 기간 안의 거래 | 없음 | `trades` (꿈 하나당 거래 하나) |
| 8 | 꿈 구해요 등록 | 기간 안에 올린 꿈 구해요 | 없음 | `dream_requests` |
| 9 | 다음 주 재방문 | 아래 대상 중, 0일부터 세어 7~13일째에 핵심 행동이 또 있는 사람 | 첫 핵심 행동일(0일)이 기간 안이고, 13일째가 이미 지난 사람 | 핵심 행동 표 5개 |
| 10 | 구슬 거래 건수·거래액 | 구슬로 산 거래 수 / 구슬 개수 합 | 없음 | `trades` — **놀이용 구슬이라 현금 매출이 아님** |
| 11 | 현금 매출 / 유료 전환율 | 0 / **미측정** | | 결제 기능이 없음 |
| 12 | AI 해몽 요청 성공 | 성공한 해몽 요청 (배포 사이트) | 해몽 요청 수 | `ai_calls` |
| 12b | AI 다시 시도 | 모델을 바꿔 다시 시도한 요청 | 해몽 요청 수 | `ai_calls.attempt > 1` |
| 12c~g | AI 시도·실패·토큰 | 모든 환경(로컬 개발·점수 시험 포함)의 시도 수, 실패 수, 입력·출력·생각 토큰 | | `ai_calls` |
| 12h | AI 비용 | **비용 미확인** | | 요율을 넣지 않음 (아래 5 참고) |

### 중복으로 세지 않게
- 꿈 저장, 판매, 구매, 꿈 구해요는 서버가 확정한 표(`dreams`·`trades`·`dream_requests`·`request_responses`)에서 바로 세요.
  새로고침이나 다시 시도를 해도 한 번만 세져요. 실패한 구매나 저장은 표에 남지 않아요.
- 첫 방문과 공유 링크 방문은 `(visitor_id, type, dedup_key)`로 한 번만 남아요.
- 공유 시도, 완료, 복사는 누를 때마다 세요. 시도 횟수를 보는 지표라서 그래요.

### 이렇게 읽으면 안 돼요
- 공유 완료(5b)나 링크 복사(5c)는 상대가 링크를 받았다는 증거가 아니에요. 상대가 실제로 열었는지는 6 공유 링크 방문으로 보세요.
- 구슬 거래액(10)은 놀이용 구슬 숫자예요. 매출로 보면 안 돼요.
- 등급 희귀도("설정상 상위 N%")는 등급표에 정한 목표 비율이에요. 실제로 나온 꿈의 비율을 보려면 `dreams.grade`를 따로 세야 해요.

## 4. 유입 경로가 이어지는 방식
1. 페이지를 처음 열면 `src/app/tracker.tsx`가 `/api/track`에 방문을 알려요. 서버는 쿠키가 없으면 새 방문자 번호를 만들고 `first_visit`을 남겨요.
2. 공유 버튼으로 만든 링크에는 `?via=share` 또는 `?via=copy`가 붙어요. 이 링크로 들어오면 `share_visit`을 남기고, 주소에서 `via`를 지워요.
3. 로그인 상태로 방문하거나 닉네임을 정하면 `session_link`가 같은 방문자 번호와 계정을 이어 줘요.
   그래서 익명으로 시작하기 전에 어디서 들어왔는지도 계정과 연결돼요. 로그인 방식(쿠키·세션)은 바꾸지 않았어요.

## 5. AI 원가
- 해몽을 한 번 요청하면, 모델을 한 번 시도할 때마다 `ai_calls`에 한 줄이 남아요.
  남는 값은 용도(`interpret` = 해몽, `reading_backfill` = 예전 꿈 채우기), 모델, 성공/실패, HTTP 상태, 걸린 시간, Gemini가 알려 준 토큰 수예요.
  무료 등급에서 한 호출도, 실패한 호출도 모두 남아요.
- 실패한 시도에는 대부분 토큰 정보가 없어요. 그런 시도는 토큰 합계에서 빠져요.
- 비용 환산: `scripts/metrics.ts`의 `AI_PRICES`에 **공식 요금표에서 확인한** 모델별 요율(백만 토큰당 USD)을 넣으면 환산해요.
  넣지 않은 모델은 "비용 미확인"으로 보여요. 지금은 무료 등급이라 실제 청구액은 0이에요.

## 6. 개인정보
- 행동 기록에 넣는 건 기록 종류, 화면 종류(`sale`·`market` 등), 꿈이나 꿈 구해요의 id, `via`, 공유 방식, 가짜 문 이름뿐이에요.
  꿈 원문, 해몽, 닉네임, 이메일, 인증 정보, 전체 주소(URL)는 넣지 않아요.
- 누가 보냈는지는 서버가 쿠키와 로그인 정보로 정해요. 브라우저가 보낸 계정 id는 믿지 않아요.
  브라우저가 `events`에 직접 쓸 수 있는 건 예전 가짜 문 기록뿐이에요 (0011에서 보안 규칙을 좁힘).
- 사용자 화면의 개인정보 안내 페이지(`/privacy`)는 2026-10-30 사용자 결정으로 뺐어요.

## 7. 한계
- 로컬 개발 서버도 같은 Supabase DB를 써요. 그래서 내 컴퓨터에서 저장한 꿈이나 거래도 2~10번 지표에 섞여요.
  내 시험 계정을 `metrics_excluded_users`에 넣어서 빼 주세요. 방문·공유 기록(`events`)은 `app_env = 'production'`만 세요.
- 쿠키를 지우거나, 시크릿 창이나 다른 브라우저로 오면 새 방문자로 세요.
- `/api/track`은 누구나 부를 수 있어서, 마음먹으면 방문 수를 부풀릴 수 있어요. 숫자가 이상하게 튀면 `events`를 직접 확인해 보세요.
- 0011을 적용하기 전에 생긴 방문·공유·AI 호출은 기록이 없어요. 예전 공유 기록 `sale_share_click`·`sale_link_copy`는 지표에 넣지 않아요.
