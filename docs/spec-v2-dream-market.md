## 프롬프트 본문 (여기부터 복사)

나는 프로그래밍 초보인 대학생이고, "꿈툰"이라는 모바일 웹 서비스의 MVP를 만들고 싶어.
각 단계를 시작하기 전에 무엇을 할지 짧게 설명해 주고, 단계가 끝나면 내가 브라우저에서 확인하는 방법을 알려준 뒤 멈춰 줘. 내가 모르는 용어가 나오면 한 줄로 쉽게 풀어 줘.

### 서비스 한 줄 설명
좋은 꿈을 친구에게 사고파는 앱. 사용자가 꿈을 말하면 AI가 해몽하고 길몽 등급을 매긴 뒤 4컷 웹툰으로 포장해 주고, 친구가 그 꿈을 "꿈 구슬"이나 "응원 한마디"로 사면 매매 증서가 발급된다.
브랜드 배경: 삼국유사에서 문희가 언니 보희의 꿈을 비단 치마 한 벌에 사서 왕비가 된 이야기. 톤은 "재미로 주고받는 꿈의 기운".

### 기술 스택
- Next.js (App Router, TypeScript) + Tailwind CSS, 모바일 우선 화면
- Supabase: Auth(이메일 매직링크 또는 Google 로그인), Postgres DB, Storage
- 배포: Vercel
- 받아쓰기 + 해몽 글: Google Gemini API (Flash 계열 모델, 음성 파일 입력 지원). 무료 등급 사용
- 그림: OpenAI 이미지 API `gpt-image-1-mini` (중간 품질), 컷마다 1장, 4장 병렬 요청
- 이미지 합성(4컷, 판매 카드, 매매 증서): 서버에서 코드로 (`@vercel/og`/satori 또는 `sharp`). 한글 글자·말풍선·배지는 이미지 모델이 아니라 합성 단계에서 폰트로 얹을 것. 폰트는 Google Fonts의 Jua(말풍선), Gowun Batang(제목·증서), Gowun Dodum(본문)
- 모든 API 키는 `.env.local`에만, 브라우저 코드에 절대 노출 금지. AI 호출은 전부 서버(Route Handler/Server Action)에서

### 핵심 화면
1. **홈 / 내 꿈 서랍**: 내가 기록한 꿈, 산 꿈, 구슬 잔액, 행운 전달 도장 수
2. **꿈 올리기**: 녹음(최대 60초) 또는 글쓰기 → 받아쓴 글 수정 → "그리지 않을 장면" 체크(선택) → 공개 범위(나만 보기 / 공유용)
3. **꿈 결과**: 4컷 웹툰, 등급 이름 + 알파벳(작게), 운 종류 태그, 해몽 결론 한 줄, 상세 해몽, 행운의 색·물건. 버튼: [이 꿈 팔기] [이미지 저장] [6·8컷으로 다시 그리기(가짜 문)]
4. **판매 카드 페이지** (공유 링크로 열림): 흐리게 처리한 웹툰, 등급, 운 태그, 해몽 한 줄, 가격, 판매자 닉네임, 마감까지 남은 시간. 버튼 [꿈 사기]
5. **구매**: B등급은 응원 한마디(필수, 50자 이내) 입력으로 구매. A등급 이상은 구슬 차감 + 응원 한마디(선택)
6. **매매 증서**: 꿈 이름, 등급, 꿈값, 판 사람, 산 사람, 날짜, 응원 한마디, 두 사람 도장. 문구 "신라의 문희처럼, 이 꿈의 기운은 이제 당신의 것입니다". 이미지 저장·공유
7. **꿈 구해요**: "내일 OO인데 합격운 꿈 구해요" 요청 작성 → 공유 링크 → 친구들이 자기 꿈을 골라 응답 → 요청자가 하나를 삼
8. **행운 후기**: 구매 3일 뒤 구매자 화면에 "그 일 잘 됐어요?" 카드 → [잘 됐어요] 누르면 판매자에게 "행운 전달 성공 ✨" 도장 +1

### 등급과 가격 (AI가 0~100점 → 등급)
| 등급 | 이름 | 목표 비율 | 점수 구간(초기값) | 꿈값 |
|---|---|---|---|---|
| SSS | 천운몽 | 1% | 97~100 | 1,000 구슬 |
| SS | 대길몽 | 4% | 90~96 | 700 구슬 |
| S | 길몽 | 10% | 78~89 | 500 구슬 |
| A | 소길몽 | 20% | 60~77 | 300 구슬 |
| B | 평몽 | 35% | 30~59 | 응원 한마디 (무료) |
| C | 액땜몽 | 30% | 0~29 | 판매 불가 |
- 점수 구간은 설정 파일(config)로 빼서 나중에 비율을 보며 고칠 수 있게
- 운 종류 태그: 재물운, 합격운, 연애운, 건강운, 귀인운 (꿈 하나에 1~2개)
- 화면에는 이름(대길몽)을 크게, 알파벳(SS)은 작게

### 꿈 구슬 (현금 환급 불가, 앱 안에서만)
- 버는 곳: 가입 1,000 / 매일 첫 접속 10 / 꿈 기록 30(하루 3회까지) / 친구 초대 가입 300 / 내 꿈이 팔림 = 판매가 전액
- 쓰는 곳: 꿈 사기, 증서 꾸미기(가짜 문), 6·8컷(가짜 문)
- 광고 보고 구슬 받기: 버튼만 두고 가짜 문
- 모든 증감은 `bead_ledger`에 기록하고 잔액은 그 합으로 계산

### 거래 규칙 (반드시 서버/DB에서 강제)
- 판매 가능: A등급 이상은 구슬, B등급은 응원 한마디. C등급은 판매 버튼 숨김
- 등급은 AI가 정하고 판매자는 수정 불가
- 꿈 기록 후 24시간 안에만 판매 등록 가능, 판매 마감도 기록 후 24시간
- 한 꿈은 한 명에게 한 번만 팔림, 산 꿈은 되팔 수 없음
- 판매자 하루 판매 3건까지, 자기 꿈은 자기가 못 삼
- 구매는 Postgres 함수(RPC) 하나로 처리: 잔액 확인 → 구슬 이동 → 꿈 소유 표시 → 거래 기록이 한 트랜잭션 안에서 일어나서, 두 명이 동시에 사도 한 명만 성공해야 함
- 모든 화면에 "재미로 주고받는 꿈의 기운" 표기. 로또·복권 관련 문구 금지

### AI 해몽 프롬프트 (Gemini에 그대로 사용, JSON만 출력)
```
당신은 한국 전통 꿈 해몽에 밝고 다정한 말투를 쓰는 "달빛 해몽가"입니다.
사용자의 꿈을 해몽하고, 길몽 점수와 4컷 웹툰 콘티를 만들어 주세요.

[입력]
- 꿈 내용: {{dream_text}}
- 그리지 않을 장면(선택): {{excluded_scenes}}
- 내일 있는 일(선택): {{tomorrow_event}}
- 주인공 캐릭터 설명: {{character_desc}}

[규칙]
1. 꿈 내용을 지어내지 말고 빈 부분만 자연스럽게 이어 붙이세요. 그리지 않을 장면은 콘티에서 빼세요.
2. 4컷: 1~3컷은 꿈 장면, 4컷은 달빛 해몽가가 해몽 결론 한 줄을 말하는 장면.
3. 대사는 컷당 20자 이내 한국어 구어체. scene 묘사는 영어로, "no text in image" 포함.
   실제 브랜드명(페라리 등)은 "fictional, original design, no logo"로 바꿔 묘사하세요.
4. luck_score(0~100)는 한국 전통 해몽 상징 기준으로 매기세요.
   용·봉황·임금=최상, 돼지·조상·큰불·똥=매우 높음, 맑은 물·금은보화·흰 동물=높음,
   꽃·과일·하늘 날기·합격=보통 이상, 일상 장면=중간, 이빨 빠짐·추락·쫓김=낮음.
   대부분의 꿈은 30~70점 사이여야 합니다. 90점 이상은 아주 드물게만.
5. luck_tags는 [재물운, 합격운, 연애운, 건강운, 귀인운] 중 1~2개.
6. 해몽은 3문장 이내, 흉몽도 "액땜"처럼 안심으로 끝내고, 내일 있는 일이 있으면 마지막 문장을 거기에 연결.
7. 자해·자살, 성적 내용, 실존 인물 비방이 있으면 safety_flag=true, panels는 빈 배열.

[출력]
{
  "title": "꿈 제목 12자 이내",
  "symbols": ["돼지", "금화"],
  "luck_score": 72,
  "luck_tags": ["재물운"],
  "headline": "해몽 결론 한 줄 (20자 이내)",
  "interpretation": "상세 해몽 3문장",
  "lucky": {"color": "빨강", "item": "자동차 키링"},
  "panels": [
    {"no": 1, "scene": "english, no text in image", "dialogue": "대사"},
    {"no": 2, "scene": "...", "dialogue": "..."},
    {"no": 3, "scene": "...", "dialogue": "..."},
    {"no": 4, "scene": "the moonlight dream interpreter ...", "dialogue": "해몽 결론"}
  ],
  "safety_flag": false
}
```
- safety_flag가 true면 그림을 그리지 말고 "힘든 꿈을 꾸셨네요" 안내와 자살예방상담전화 109 등 상담 창구를 보여줄 것
- 이미지 생성 시 주인공 캐릭터 레퍼런스 이미지(`/public/characters/`)와 달빛 해몽가 레퍼런스를 함께 넣고, 고정 화풍 문장을 앞에 붙일 것

### 데이터베이스 (Supabase, RLS 켜기)
- `profiles`(id, nickname, created_at)
- `dreams`(id, owner_id, original_owner_id, text, excluded_scenes, visibility, title, symbols, luck_score, grade, luck_tags, headline, interpretation, lucky, panels, image_url, created_at, sale_status[none/on_sale/sold], price_type[beads/cheer], price, sale_expires_at)
- `trades`(id, dream_id, seller_id, buyer_id, price_type, price, cheer_message, certificate_url, created_at, review_status[pending/good/skip])
- `bead_ledger`(id, user_id, delta, reason, ref_id, created_at)
- `dream_requests`(id, requester_id, luck_tag, message, expires_at) / `request_responses`(id, request_id, dream_id, responder_id)
- `luck_stamps`는 trades.review_status='good' 집계로 계산
- `events`(id, user_id, type, meta, created_at): 가짜 문 클릭, 공유 클릭 등 기록
- 음성 파일은 받아쓰기 직후 삭제, 꿈 텍스트는 본인과 구매자만 열람

### 만들지 않을 것 (버튼만 두고 누르면 "곧 열려요! 알림 받을 이메일" 모달 + events 기록)
6·8컷 그리기, 광고 보고 구슬 받기, 증서 꾸미기, 천운몽 경매, 장터방(그룹), 구슬 유료 충전

### 진행 순서 (단계마다 멈추고 내 확인 받기)
1. 프로젝트 생성, Supabase 연결, 로그인, 닉네임 설정, 가입 시 구슬 1,000 지급, 홈 화면
2. 꿈 올리기(글쓰기 먼저) → Gemini 해몽 JSON → 결과 화면에 텍스트로 등급·태그·해몽 표시. 테스트 꿈 10개로 점수 분포를 표로 보여줘
3. 4컷 이미지 생성 + 합성(1080×1920 세로, 제목·말풍선·등급 배지·"AI로 생성된 이미지" 표시)
4. 판매 등록 → 판매 카드 페이지(흐린 웹툰) → 구매 RPC(구슬/응원 한마디) → 매매 증서 이미지 생성
5. 녹음 + 받아쓰기, 꿈 구해요, 행운 후기 도장, 가짜 문 버튼들
6. Vercel 배포, 공유 링크 미리보기(OG 이미지), 친구 5명이 써 볼 수 있는 상태로 마무리
각 단계마다 꿈 1편 처리에 드는 대략적인 API 비용도 알려줘.

## 시작 전에 준비할 것
- Google AI Studio에서 Gemini API 키 (무료 등급, 카드 불필요한 경우가 많음. 단 무료 등급은 입력 내용이 구글 서비스 개선에 쓰일 수 있음 → 모르는 사용자를 받기 전에 유료 전환 또는 개인정보 처리방침에 고지)
- OpenAI API 키 (그림용. 결제 카드 등록 후 $5 충전, 월 사용 한도 $10 설정, 자동 충전 끄기)
- Supabase, Vercel, GitHub 무료 계정
- 캐릭터 이미지: 주인공 프리셋 5장 + 달빛 해몽가 1장 (character-prompts.md 참고). 프로젝트의 `/public/characters/`에 넣기
- 비용 감: 꿈 1편 ≈ 글 0원(Gemini 무료) + 그림 4장 약 60원
